# Круг — личная CRM по знакомым

Телеграм-бот на своём VPS. Держит базу знакомых, считает, с кем связь провисает, и раз в день присылает короткий список: кому написать сегодня и почему.

В основе — слои Данбара, досье по схеме FORD и ритм касаний. Подробности методик в `personal-crm-concept.md`.

## Что уже работает

- Люди: круги 0–4, теги, город, контакты, обстоятельства знакомства
- Досье по блокам FORD: семья, работа, увлечения, планы, зацепки, «не трогать», подарки
- Лог общения: переписка / звонок / встреча — в одно нажатие
- Индекс состояния связи: сколько дней тишины против желаемого интервала
- События с датами: дни рождения (ежегодные), защиты, переезды, годовщины
- Обещания в обе стороны, со сроком
- Утренний дайджест в 10:00
- Полнотекстовый поиск по имени, городу, тегам, досье и заметкам
- Импорт из CSV
- Мини-апп: карта кругов, добавление, правка, архив и удаление карточек
- Семья с автоматическим достраиванием связей, питомцы, аватары, оценка отношений
- Режим постепенной ручной разметки: норма в день, подсказки, контроль пробелов
- Доступ только владельцу по telegram id

## Запуск

```bash
cp .env.example .env      # BOT_TOKEN от @BotFather, OWNER_ID от @userinfobot
npm install
npm run dev
```

## На VPS

```bash
git clone <репозиторий> && cd personal-crm
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f
```

Без докера — через systemd:

```ini
# /etc/systemd/system/crm.service
[Unit]
Description=Personal CRM bot
After=network.target

[Service]
WorkingDirectory=/opt/personal-crm
ExecStart=/usr/bin/node dist/src/index.js
Restart=always
EnvironmentFile=/opt/personal-crm/.env
User=crm

[Install]
WantedBy=multi-user.target
```

```bash
npm ci && npm run build
systemctl enable --now crm
```

## Бэкап

База — один файл. Достаточно cron:

```bash
0 4 * * * sqlite3 /opt/personal-crm/data/crm.db ".backup '/opt/backups/crm-$(date +\%F).db'"
```

Это данные о живых людях. Держи бэкапы на своём же диске или в шифрованном виде — не в чужом облаке.

## Мини-апп

Карта кругов и удобная форма добавления. Живёт в том же процессе, что и бот, на порту 3000.

### Посмотреть сразу, без домена

```bash
# в .env
ALLOW_INSECURE=1
```

```bash
docker compose up -d --build
ssh -L 3000:127.0.0.1:3000 root@ТВОЙ_IP
```

Пока туннель открыт, приложение доступно на `http://localhost:3000` в обычном браузере — удобно проверить с ноутбука. Мобильный вид включается в devtools.

`ALLOW_INSECURE=1` **отключает проверку подписи Telegram**. Это режим отладки: с ним любой, кто дотянется до порта, получит доступ к базе. Порт в `docker-compose.yml` привязан к `127.0.0.1`, поэтому снаружи он закрыт, но перед боевым использованием флаг нужно вернуть в `0`.

### По-настоящему: домен и HTTPS

Telegram открывает Mini App только по HTTPS с валидным сертификатом. Нужен домен, направленный A-записью на IP сервера.

```bash
apt install -y nginx certbot python3-certbot-nginx

cat > /etc/nginx/sites-available/crm <<'EOF'
server {
    server_name crm.твой-домен.ru;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

ln -s /etc/nginx/sites-available/crm /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d crm.твой-домен.ru
```

Затем в `.env`:

```
PUBLIC_URL=https://crm.твой-домен.ru
ALLOW_INSECURE=0
```

`docker compose up -d --build` — и в боте появится кнопка меню «Круг», плюс команда `/app`.

### Правка карточек

В карточке человека — кнопка «Редактировать». Там меняется всё: имя, круг, теги, свой интервал вместо интервала круга, блоки досье, контакты, даты.

Дата последнего общения правится не перезаписью, а добавлением контакта задним числом: история остаётся целой, а `last_contact` по-прежнему выводится из неё.

**Архив против удаления.** Архив прячет человека из карты и напоминаний, но сохраняет всю историю — это то, что нужно в 95% случаев, когда связь просто сошла на нет. Восстановить можно на вкладке «Разметка». Удаление стирает человека вместе с заметками, контактами и обязательствами, и предназначено только для дублей и опечаток. Обе кнопки требуют второго нажатия для подтверждения.

### Семья, питомцы, аватары

Экран правки разбит на раскрывающиеся блоки: основное, цели и мечты, остальное досье, семья, питомцы, контакты и даты.

**Цели и мечты** вынесены в отдельный блок намеренно. Это самая ценная часть досье и самая пустая у большинства: один вопрос по ней стоит десяти дежурных сообщений.

**Оценка отношений** — от 1 до 5, «как вам вместе». Отдельно от полей `interest` / `difficulty` / `risk`: те про стратегию контакта, эта про то, насколько с человеком хорошо.

**Семья.** Добавляешь мужа и двоих детей — система сама достраивает остальное: дети одного родителя становятся братьями и сёстрами, супруг родителя становится родителем детей. Производные связи помечены как «авто» и пересчитываются заново при каждой правке, поэтому не разъезжаются после удалений.

Родственники создаются как **карточки-заглушки**: они видны в блоке семьи, но не занимают место в круге Данбара, не попадают на карту и не порождают напоминаний. Иначе пятилетний ребёнок оказался бы в списке «кому написать», а база из 200 человек мгновенно раздулась бы до 500. Кнопка «в круг» превращает заглушку в полноценную карточку, когда с человеком действительно нужно поддерживать связь.

**Питомцы** с кличкой, видом, породой и датой рождения. Дата питомца становится напоминанием про хозяина: спросить про кота часто теплее, чем спросить про работу.

**Аватары** для людей и питомцев. Картинка уменьшается до 320 px прямо в браузере через canvas, поэтому серверу не нужен ни sharp, ни другие нативные зависимости. Файлы лежат в томе рядом с базой и переживают пересборку контейнера.

### Как устроена защита

Telegram передаёт в приложение подписанный `initData`. Сервер проверяет подпись через HMAC-SHA256 с секретом, выведенным из токена бота, и сверяет `auth_date` — данные старше суток отклоняются. После этого проверяется, что id пользователя совпадает с `OWNER_ID`. Подделать это, не зная токена, нельзя.

Vue отдаётся со своего же сервера (`/vendor/vue.js`), а не с CDN — на одну внешнюю зависимость меньше.

## Наполнение базы вручную

Система рассчитана на то, что база набирается постепенно — по несколько человек в день.
Два правила, без которых этот режим ломается:

**1. Человек без даты последнего общения не участвует в напоминаниях.**
Иначе каждый только что добавленный знакомый мгновенно становился бы «риском», и через неделю дайджест превратился бы в стену мусора. Такие люди видны в `/gaps`, а не в списке на сегодня.

Поэтому при добавлении указывай ключ `был:` — хотя бы примерно:

```
/add Костя Лапшин #бег круг:1 был:08.07
```

**2. Вспоминай кластерами, а не по алфавиту.**
Память достаёт людей по контексту: «кто был на той свадьбе», «кто сидел рядом в универе». `/roster` показывает прогресс и выдаёт подсказку, откуда доставать следующих. `/next` — следующая подсказка.

| Команда | Что делает |
|---|---|
| `/roster` | Прогресс разметки и подсказка на сегодня |
| `/next` | Следующая подсказка для вспоминания |
| `/gaps` | У кого нет даты последнего общения |
| `/target 200` | Цель по размеру базы |
| `/quota 5` | Дневная норма |

Строчка о разметке висит в хвосте дайджеста и исчезает сама, когда цель взята.

## Команды

| Команда | Что делает |
|---|---|
| `/today` | Кому написать сегодня |
| `/add Аня Соколова #бег круг:2 др:12.04 был:02.07 город:Москва "познакомились на забеге"` | Добавить человека |
| `/find юрист` | Поиск по всему |
| `/f семья Дочь Мира, 5 лет` | Дописать в досье открытого человека |
| `/app` | Открыть карту кругов |
| `/stats` | Заполненность кругов против ёмкости Данбара |
| `/circles` | Справка по слоям |
| `/lead 21` | За сколько дней поводы начинают проявляться (одно значение для всех дат, включая питомцев) |

Свободный текст без команды — тоже поиск. Если совпадение одно, сразу открывается карточка.

Ключи в `/add`: `круг:` `др:` `был:` `тг:` `тел:` `город:`, теги через `#`, обстоятельства знакомства в кавычках.
`был:` — дата последнего общения, самый важный ключ: без неё человек молчит в напоминаниях.

## Импорт

```bash
npm run import -- ./people.csv
```

Колонки: `name, circle, city, telegram, phone, tags, birthday, last_contact, context`.
Теги через точку с запятой, `birthday` в формате `12.04` или `12.04.1991`, `last_contact` в `YYYY-MM-DD`.

`last_contact` лучше заполнить хотя бы примерно: без него все 200 человек в первый же день окажутся в просрочке и дайджест станет бесполезным.

## Структура

```
src/
  config.ts            переменные окружения
  db/
    index.ts           соединение + раннер миграций
    migrations/        SQL, применяются по одному разу
    types.ts           типы строк
    repo/              people, timeline (контакты и заметки), agenda (события и задачи)
  domain/
    circles.ts         слои Данбара, интервалы, ёмкости
    family.ts          родство, автовывод сиблингов, карточки-заглушки
    dates.ts           даты, ближайшее наступление события, склонения
    parse.ts           разбор строки быстрого добавления
    signals.ts         ядро: сбор поводов, рост событий, индекс связи
  bot/
    auth.ts            доступ только владельцу
    ui.ts              карточка, дайджест, клавиатуры
    handlers/          команды и колбэки
    state.ts           ожидание ввода (в памяти)
  server/
    index.ts           HTTP-сервер, статика, защита API
    auth.ts            проверка подписи initData
    api.ts             REST для мини-аппа
    layout.ts          раскладка узлов по кругам и секторам
public/                мини-апп: index.html, app.js (Vue 3), style.css
  jobs/digest.ts       утренняя рассылка
scripts/import-csv.ts
```

Два решения, которые стоит держать в голове при доработке:

1. **Дата последнего контакта не хранится полем.** Она выводится из таблицы `interaction`. Так сохраняется история и можно будет отличать переписку от встречи по весу.
2. **Люди без единого контакта исключены из расчёта тишины.** Это не баг, а условие, при котором систему можно наполнять постепенно, не утонув в ложных сигналах.
3. **Миграции запускаются при импорте `db/index.ts`, а не из `main()`.** Репозитории готовят prepared statements на верхнем уровне модуля, а ESM выполняет импорты раньше тела вызывающего файла — к моменту `prepare` таблицы уже должны существовать.
